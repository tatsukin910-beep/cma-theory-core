# 運用ルール (Version 2.2)

## 1. このスキルの目的
Google（Gemini）と Grok の2つのAIを使い分け、役割を明確に分離することで、研究・日常作業・外部観察の管理コストを下げ、作業の再現性と安全性を担保する運用ルールである。

## 2. 2大AIの役割分担

### Gemini（Googleエコシステム：メイン・作業の土台）
**「手元の資料を使って書く・整理する・深める」担当**
- **研究資料の整理・照合:** Google Drive / Docs 内の資料管理、要約、Theory Definition との突き合わせ。
- **学術・執筆・指示作成:** 論文原稿やnoteの下書き、論理構造の点検、APA 7th準拠の確認、Antigravity向けの曖昧さのないIssue指示書作成（5層境界の厳格なチェック含む）。
- **長文脈の考察:** 5層（孤立・依存・正常化・制度的不応答・身体化）の説明文の調整。
- **開発・ローカル連携:** Antigravity / Cloud Shell を用いたコード・Webサイトの保守。

### Grok（Xエコシステム：Xの空気感・観察専用）
**「外の声を拾って、研究の入口や発信のヒントにする」担当**
- **リアルタイムの空気感把握:** X上の当事者の声、日常の困りごとの温度感、トレンドの観察。
- **定点観測:** 特定キーワードや関心領域のアカウント周辺の投稿収集。
- **外部視点・反応の確認:** 「この切り口が外からどう見えているか」の客観的・批判的な確認。

## 3. 基本の連携フロー（6層サイクル）
1. **観測（X / Grok）**: 外の社会的温度感をキャッチする。
2. **構造化（Gemini）**: 拾った声をCMA理論（5層）に接続し、Antigravity向けのタスク指示に落とし込む。
3. **Issue化（GitHub）**: GitHubのIssueまたはローカル指示書でタスクを管理する。
4. **実装（Antigravity）**: ローカル環境でファイルやコードの直接編集・テストを行う。
5. **差分確認・コミット・デプロイ（人間 ＋ gcloud/git）**: **必ず `git diff` で差分を確認してから**コミットし、デプロイする。
6. **還元（X Subscriptions）**: プロセスの試行錯誤そのものを支援者へ共有する。

## 4. 運用原則
- **差分確認の徹底**: 変更は必ず `git diff` で確認してからコミットする（AI任せにしない）。
- **正本の遵守**: CMA理論の正本は Zenodo の Theory Definition v2.0（DOI: 10.5281/zenodo.21876469）。
- **事実・解釈・仮説の分離**: 一次資料（事実）、著者の解釈、自身の仮説を混同させない。

## 5. Antigravity（ローカル自律エージェント）基本運用フロー

### 位置づけと基本原則
- **位置づけ**: ローカルファイルを直接読み込み・編集・検証する自律エージェント型作業環境。
- **人間の役割**: 変更のレビュー・差し戻し、および最終的な Git コミット/プッシュの承認（ゴーサインの権限は必ず人間が保持する）。
- **基本リズム**: 「1指示＝1目的＝1コミット」で小さく刻み、差分を安全に積み上げる。

### 起動手順
1. **アプリ起動**: デスクトップのショートカットまたは Windows スタートメニューから「Antigravity」を起動する。
2. **初期状態の確認**: 起動後、エージェントとの対話パネルおよびワークスペース（作業領域）が表示されていることを確認する。

### 操作フロー（標準サイクル）
1. **ワークスペース（作業フォルダ）を開く**: 作業対象のリポジトリのみを開く（例: `C:\Users\tatsu\.gemini\antigravity\scratch\cma-theory-core`）。親ディレクトリを含めずスコープを限定する。
2. **エージェントにタスクを指示する**: 対象ファイルと目的を具体的に伝える。
3. **自律編集と差分プレビューの確認**: 画面上の差分（赤：削除／緑：追加）を確認し、意図と異なる場合は **「Reject」** で即座に差し戻す。
4. **変更内容の最終検証**: 必要に応じてターミナルで `git status` と `git diff` を実行し、意図しない変更がないか精査する。
5. **コミット・プッシュ（承認と記録）**: 人間側で最終確認した上で、手動でコミットおよびプッシュを実行する。

### 安全運用の確認項目
- [ ] **スコープ制限**: ワークスペースに余計なフォルダが含まれていないか
- [ ] **単一責務**: 1回の指示に複数の無関係な修正を混在させていないか
- [ ] **差分レビュー**: 自動実行・サイレント承認に任せず、画面差分を目視確認したか
- [ ] **Working Treeの保全**: 作業完了時に `git status` で不要な変更が残っていないか
